# 候选排序与实验协议核验

日期：2026-10-04。性质：独立协议审计与下一轮设计建议；不是新增实验结果。读取了固定代码快照、原架构、2026-10-03 最小筛查协议、逐图指标、选择文件和训练日志；没有修改原代码、训练或重新推理。

## 1. 先给出独立判断

**现有证据不足以选出三个已经有效的创新方向。可以选出一个工程收益明确的 E，以及两个值得继续检验的方法方向。建议研究组合为 E、D、C；其中 C 的入围依据是可检验的机制问题和修复价值，而不是它已经比 F 效果好。**

必须把三种排序分开：

1. 按“已有明确收益”排序：E 第一；A–D/F 均未证明稳定增量；B_ADAPT/G 未完成。BASE_CONT 的继续训练收益不属于 A–G 新模块。
2. 按“旧实验均值的正号一致性”排序：E 后，F 在 validation/UIEB/LSUI 相对均匀专家的均值都微正，D 在前两者微正、LSUI 微负，C 路由在两测试集微负。但 F 的幅度接近零，不能把三个正号当三次独立重复。
3. 按“新一轮研究投资价值”排序：E 提供便宜诊断与效率基线，D 提供最接近原最小协议且易隔离的相位实验，C 提供可直接干预的错误先验、严格 null 和条件融合机制；F 暂存为备选，A/B/G 暂缓。

因此，若必须完全机械地根据旧分数选三项，可以得到 E/D/F；如果目标是纠正机制身份、争取论文贡献，我更推荐 E/D/C，但必须说明这种选择包含研究判断，不能写成“数据已经证明 C 优于 F”。也不应给没有统计依据的成功概率百分数。

## 3. 上轮结论需要纠正的地方

### 3.1 0.10 dB 不是创新判定定理

原协议的 +0.10 dB 是有限资源筛选时预先设定的**实际收益门槛**，不是统计显著性的通用标准，也不是论文创新的必要充分条件。

- 0.11 dB 若来自不公平控制、数据重叠或选择偏差，仍不能证明方法有效。
- 0.05 dB 若稳定、质量不退化且计算量大幅降低，可能支持明确的效率贡献。
- 0.00 dB 的干净平均差，若严格证明错误先验场景下更安全且成本合适，可能支持鲁棒性贡献。
- 已有 DDIM 带来 40 倍加速，也不会因为收益大就自动成为本项目的新算法。

下一轮分别定义质量、鲁棒性、效率三种主张，不能在看过结果以后选择最有利的一种来包装成功。

### 3.2 有意简化不等于实现错误

应以最后冻结的 `EXPERIMENT_FRAMEWORK_SINGLE_SEED_AG_7DAY_20261003.md` 为上一轮执行身份依据，而不是只拿完整版架构反推失败。

| 项目 | 最新最小协议原本允许 | 应修正或补验的部分 |
|---|---|---|
| A | 全局三通道有效系数；A_SPLIT 复制初始化；暂缓空间场；共享 linear RGB / distance proxy / softplus | cycle 的有效区域 mask、未裁剪 renderer/L1 契约、梯度和物理语义；没有真值时不能称恢复真实系数 |
| C | c_additive 保留旧的 12 通道入口和高频通路；首次不做效用标签 | 仍明确要求交叉注意力；实际逐位置点积门控并不等价；null 经过有 bias 输出头可能不严格为零；直方图不应伪装为空间图 |
| D | 明确规定浅层 phase 与相同结构 Sobel；D2 先做，D1 小波残差扩散暂缓 | 浅层不是偏差；需核验数值尺度、实际使用、低幅值噪声与跨域行为；不能据 D2 否定 D1 |
| F | 四小专家+null，不复制四套 U-Net，不做目标域适配 | WaterConditionEncoder 退化为七个全局均值，hist mean 信息可能退化；需要检查容量、负载与专家多样性 |

“恢复完整版”是一个新的、更昂贵的研究实验，不能承诺能弥补所有负结果。

## 4. 冻结实验身份，先处理父模型和测试暴露

### 4.1 父模型的历史胜者偏差

证据包有 45 个历史完整源验证目录，85000 步父 checkpoint 是该历史验证序列的 best；本轮又比较了 85000/220000/225000 等候选。对同一 91 图多次选择 best，会使其 validation 分数偏乐观。这是一个合理的选择偏差解释，**不是已证实的导致 BASE_CONT validation 下降的原因**。

当前现象：BASE_CONT 比父模型在源 validation 低 0.142752 dB，而在 UIEB/LSUI test 高 0.573922/0.729533 dB。下一轮不得据已看过的测试分数改成以 BASE_CONT 为父模型并宣称预注册最优选择。

省资源做法：固定同一个已有 85000 步 checkpoint 的 hash，明确所有主张条件于这个父模型；另保留 225000 步已有 checkpoint 作为独立于新方向筛选的 checkpoint 敏感性诊断。第二个历史 checkpoint 仍不是独立父训练种子。

### 4.2 已看过的 test 仍可报告，但已经不是下一轮的新盲测

2026-10-03 的 UIEB/LSUI test 当时在冻结后评估，原结果依然有效。现在它们已经被研究者用于判断 C/D/F 的下一轮研究优先级，后续不能再称为“从未影响研究设计的新测试集”。

建立 `data_exposure_ledger.json`，逐数据集、scene_id 记录：父模型训练、微调训练、超参选择、诊断查看、历史测试。将旧 test 标记为 `legacy_exposed_test`，保留报告和可比性。

确认性证据需要一个新的、场景隔离且无训练暴露的 paired holdout。可优先核验服务器已持有数据中此前未训练、未评估、未查看结果的独立场景，固定规则选取；不必立即购买或大规模下载新数据。禁止从父模型已经训练过的图中重新划一个“新测试集”，也禁止按方法得分挑未见样本。若无法得到真正新 holdout，本轮结果只能升级为多微调种子的探索证据，报告不得宣称完成独立确认。

场景审计需结合来源 ID、序列/视频 ID、精确 hash、近重复候选和人工盲审。dHash 近似只是候选，不能自动判泄漏；精确 hash 为零也不能证明无相同场景 crop。

## 5. 统计方案：区分图像、场景、微调和父初始化

设同一场景组 g、微调种子 s 下的方法和控制指标分别为 m(M,s,g)、m(C,s,g)。每图平均与每场景等权平均是不同估计量，主表必须说明采用哪一个。

配对差定义为：

\[
\delta_{s,g}=m(M,s,g)-m(C,s,g),\qquad
\widehat\Delta_s=\frac{1}{G}\sum_{g=1}^{G}\delta_{s,g}.
\]

优先使用场景等权作为新主分析，逐图等权作为兼容旧报告的敏感性分析；不能只选择更好看的那一种。

报告三层结果：

1. **固定权重的图像/场景差异**：每个 s 分别对同一场景组做配对 cluster bootstrap，保存随机数种子和抽样次数。场景内多图一起抽取。
2. **固定父模型下的微调随机性**：三个独立 `finetune_seed` 的 \(\widehat\Delta_s\) 全部展示，报告均值、样本标准差、最小值。三个种子不是稳定性的终极证明；n=3 的训练分布区间很不稳定，不能依靠小样本 bootstrap 美化精度。
3. **独立父训练初始化**：若要声称对从零训练初始化普遍稳定，后续才补独立父模型及各自配对微调。三个微调 seed、三个采样 seed、三个历史 checkpoint 都不能替代这个证据。

初始确认只锁一个主方法和一个主要对照、一个主质量/鲁棒性终点；其他指标与子组为次要结果，避免每种指标都当独立成功机会。如必须并列确认三个方法或多个主终点，应在冻结文件记录比较族，并用 Holm 等方法控制家族错误率，或者明确保持探索性而不输出确认性显著结论。事后看见 D 的区间为正不能追溯称它是唯一预先指定主终点。

零均值假设 \(H_0:\Delta=0\) 与实际收益要求 \(\Delta\ge0.10\) 不同。报告效应大小、区间、种子差异和成本，不用“p<0.05”代替实用意义。

## 6. 公平训练：必须可复现且可归因

### 6.1 种子入口是真实代码任务

现有 `train.py` 直接调用 `seed_all(parent['config']['experiment']['seed'], ...)`，没有独立 `--finetune-seed` 参数。只改输出目录名不会产生独立微调种子。

服务器下一轮至少增加并持久化：`parent_seed`、`finetune_seed`、`data_seed`、`noise_seed`、`module_init_seed`、`prior_dropout_seed`、`eval_noise_namespace`。数据顺序、扩散训练 t/noise、先验 dropout 各用独立随机数生成器，避免候选多调用一次随机函数便让基线和候选的训练噪声全部错位。配对控制共享同一 seed 的样本顺序和训练噪声；不同 seed 则独立。

单独核验这些生成器的 checkpoint 保存/恢复。现有 `torch.random.fork_rng` 保护部分新模块初始化，但不自动保证不同前向分支的后续随机数流一致。common random numbers 可以减少比较方差，不能把它宣传成两种不同结构逐位相同。

### 6.2 BASE_CONT 是重置优化器的热启动控制

所有候选和继续训练控制同样从固定父参数开始、重建 Adam 和相同新增学习率日程；这不等于原训练的精确续训。若候选保留旧参数的 optimizer state 而控制重置，或反过来，就引入训练配方差异。

实际 BASE_CONT − PARENT 的收益包含“又训练了一段”和“optimizer/LR 重启配方”的共同作用，不能进一步拆成纯粹增加 steps 的因果收益。若论文需要区分重启效应，另设 `RESUME_OPTIMIZER` 诊断，按相同父权重恢复合法 optimizer state；没有状态时标记不可用，不假装重构。该诊断不是所有方法主实验的强制昂贵前提。

### 6.3 相同步数与 best-on-validation 是两种问题

独立读取全部 11 个 `selection.json` 后确认，上一轮所有已完成分支实际选中 5000 步；因此上一轮没有因 best checkpoint 步数不同而破坏主比较的事实。不能误报已有结果混比。

下一轮主归因结果固定比较同新增步数，例如 5000 对 5000、10000 对 10000。部署结果可额外报告各方法在同样候选点、同样源 validation 上选出的 best；此时用“相同选模机会下的部署结果”，不叫相同步数消融。所有比较保存 checkpoint hash、step、optimizer identity。

固定日程总长度，先在 2000/5000 查看，再继续到预定 10000；不要将 5000 当日程终点衰减完后另起新日程，却仍将其视为同一连续曲线。停止和延长必须按事先规则，同时对候选和结构控制生效。

## 7. 最小资源路线

**不重新启动 400000 步；不同时扩展 A–G；不把三个候选强制合成一个大模型。**

### 阶段 P0：只做正确性、数据和采样诊断

先完成以下条件再进入任何长训练：

- 父 checkpoint/source/config/data manifest hash 可追溯；记录当前服务器状态，不中断无关任务。
- 修正 E 计时身份与真实 NFE；固定初始噪声比较 DDIM 1/2/5/10/20/50 与 DDPM1000 的小样本机制轨迹，再完整确认保留的极少数候选。
- 比较同 I/condition 下改变 x_t、改变 t、改变初始噪声是否改变输出；记录最终图像最大/平均绝对差、PSNR、轨迹与中间 \(\hat x_0\)。几乎相同的均值不等于图像相同。
- 建立可运行的场景审计和 exposure ledger，冻结一个主方法实验要用的新 holdout（若存在）。
- 完成 D 相位与 C attention/null 的数学单元检查、父参数加载及初始零残差等价检查；输出 PASS/FAIL，而不是笼统说“数学正确”。

E 的时延应分别报告：模型已加载后的 prior、sampling、CPU/GPU transfer、图像解码、总 wall time；磁盘 I/O 是否纳入必须声明。现有 `run_e0.py` 在读取图像后才开始 prior 计时，记录的是 prior+sampling，且 peak memory 在先验计算后重置；因此原峰值不能当全系统峰值显存。使用固定分辨率/batch、预热、同步、重复测量、median/p95，比较相同硬件。不得用 NFE 比代替实测加速。

### 阶段 P1：一个方向的单种子有效性试验

建议将 E 作为所有后续实验统一基础设施，不单独训练学生。综合稿已经锁定 C 为唯一首选方法主线、D 为最多启用一次的备选；这个决定应以“可靠性机制可检验”说明，而不称 C 在旧实验中最好。两种路线的适用理由：

- 若强调最快排除/确认目前微小正信号：先 D，只训练 `BASE_CONT`、`D_SOBEL`、`D_PHASE`，采用明确的相同幅度标定/相同归一化策略，避免 phase 分支输入尺度过小而从未被有效训练。任何归一化变化要同时配控制，不能只给候选有利预处理。
- 若强调错误先验的可靠使用这一论文问题：先 C，先检验严格 null 和先验干预确有作用，再训练普通容量控制、fixed-attention、learned-router；全部使用相同 token、attention、corruption exposure，只有路由机制不同。应同时报告 BASE_CONT，不能只打败可能退化的 fixed 融合。

**C 的 oracle 闸门必须避免构造性假阴性。** Oracle 是使用参考图离线选择当前候选中最优动作的诊断上界，不是部署算法。新增残差零初始化时，各动作都可能等于父输出；直接在该状态计算 oracle gap=0 没有研究意义。必须先在 train-only 完成固定配方的 bank warmup，使候选动作真实可用，再冻结同一 bank 比较固定动作、均匀融合与路由。该 warmup 的数据、步数和成本写入方法定义。Oracle 只允许使用训练参考标签构造监督，或开发验证参考作机制诊断；不得给推理程序、新 holdout 选模或部署提供参考图。

至少报告三个上界差：oracle 减 BASE_CONT、oracle 减 uniform、oracle 减开发集选出的 best-global-action。只有最后一种差异能说明“输入相关选择”存在额外空间；如果同一个 action 几乎对所有图都最好，先用那个固定 action，不应为此训练复杂 router。开发集 best-global-action 需在一个开发子集选择并在另一个场景隔离开发子集估计差异，或使用场景分组交叉验证，避免将同样本挑最佳的乐观值误解为泛化空间。

每一主线都以同父、同 seed、同日程 2000/5000/10000 为预定观察点。2000 步只做数值与严重退化排查，不因新模块尚未适配就宣布整个方向失败。5000/10000 的进入条件、预算上限和判断指标须在运行前写入冻结 JSON。

不要自动进行 D+C 联合训练。只有两个单独模块都有通过预定门槛的证据，且理论上可能互补，再用包含 BASE、D、C、D+C 的二维消融研究交互。未通过的模块不要以“组合可能有用”绕过停止规则。

### 阶段 P2：只对锁定配置补三个微调种子

先固定一个方法、必要结构控制、学习率和所有选择规则，再用三个 `finetune_seed` 运行。若 P1 的第一 seed 完全遵循最终冻结配置且没有据其结果再调参，可以计入三种子；若已经用它反复选超参，保留作 pilot，另外三个 seed 作确认更诚实。

每种子都需要独立微调的 BASE_CONT 和必要结构控制，不能用一个 BASE_CONT 对三个候选 seed。可以复用跨方向**配置、seed、父模型和训练流完全相同**的公共 BASE_CONT；不能仅因为名称相同就复用。

若 bank warmup 也是新 C 管线的一部分，最终三个微调 seed 应各自从共同父权重训练自己的 bank，之后在该 seed 内对所有 route 控制共享它。如果只训练一个 bank，再重复三次 router，那么只能称“固定父模型、固定 bank 条件下的路由训练随机性”，不能称整个 C 微调管线经过三次独立重复。

三个种子是最低成本稳定性检查，不能承诺充分统计功效。如果三个方向都不满足预定门槛，本轮正确结果是停止扩展和报告阴性证据，而不是继续找新指标、改测试子集或自动训练三个父模型。

### 阶段 P3：一次冻结后的确认与论文材料

- 保存代码提交、配置、checkpoints、逐图/逐场景/逐种子指标、选模日志和 exposure ledger。
- 指标至少包括 PSNR、SSIM、合法且独立核验实现的 LPIPS；无参考集的 UIQM/UCIQE 只能作为描述指标，不用它们单独证明视觉真实性。
- 视觉案例名单按预先 hash 选取和全部最差失败案例组合，提供 raw、reference、BASE_CONT、结构控制、方法和差分图；不只挑改善最大图。
- 旧 UIEB/LSUI test 标为历史 benchmark；新的未暴露 holdout 一次性评估，失败也完整报告。
- 外部 baseline 以能合法取得的官方权重和官方预处理为优先，记录训练数据是否覆盖本测试集。至少一个轻量确定性增强器和一个扩散模型，若无法公平运行则不宣称 SOTA。

## 8. 预算不是 90 天：根据现有日志可估算的部分

旧实验 `train.jsonl` 的 5000 次更新累计 step 时间如下，**不含验证、加载、保存和调度开销**：

| 分支 | median 每步秒 | 5000 步累计小时 |
|---|---:|---:|
| BASE_CONT | 0.7334 | 1.0437 |
| D_SOBEL | 0.7451 | 1.0615 |
| D_PHASE | 0.7737 | 1.0973 |
| C_CONV | 0.7415 | 1.0545 |
| C_FIXED | 0.7487 | 1.0646 |
| C_ROUTED | 0.7532 | 1.0671 |
| F_UNIFORM | 0.7566 | 1.0752 |
| F_ROUTED | 0.7567 | 1.0737 |

按**旧 D 结构、原硬件**外推，三个分支 × 三个微调种子 × 10000 步的纯 step 时间约 19.2 小时，而不是六次从零 400000 步的约 90 天。这里是估算，不是本轮承诺；新的 attention、分辨率、metric、数据预处理和保存开销都可能使实际成本改变。

服务器必须在新结构上运行有代表性的短计时，记录峰值显存和稳态步时，再计算：

\[
H_{\rm plan}=\frac{\sum_j K_j\,S_j\,t_j}{3600}
+H_{\rm eval}+H_{\rm io}+H_{\rm margin},
\]

其中 j 为分支，K 是 seed 数，S 是新增步数，t 是实测每步秒。预算既记串行 wall time，也记累计设备小时；多卡并行不能把设备小时写成少量 wall time。将完整评估和失败恢复费用预留，不能只为候选留钱而没有公平控制预算。

综合稿建议新增实验累计硬上限 72 设备小时，低于该值即可因无效性或工作完成提前停止；上轮剩余预算不自动滚入。一个可审核的初始分账为：诊断/实现实测最多 8 小时，训练最多 44 小时，评估与导出至少预留 12 小时，恢复/不可预见费用 8 小时。各项不是必须花满的配额。

若 5–6 个分支 × 3 个微调 seed × 10000 步，沿用旧约 0.75 s/step，需要约 31–38 纯训练小时；若真实 cross-attention 达 1.5 s/step，则约 62–75 小时，已经无法在 72 小时内加上完整评估。必须在 100–200 个有代表性稳态步之后更新预算：优先削减不必要的 pilot、采用在看效果之前确定的较低 token/通道档位，或统一降低所有方法与控制的训练步数；不得删必要控制、只跑部分种子却将状态写为完成。若连最低可解释方案也超预算，安全停止并输出可复核的预算缺口。

## 9. 成功、暂停、停止与验收

建议服务器冻结时选择一种中心主张，不在结果出来后切换：

| 主张 | 主判据 | 必要附加条件 |
|---|---|---|
| 干净质量改善 | 对同预算结构控制与 BASE_CONT 的预定平均质量差达到实际收益要求，例如继续使用 +0.10 dB | SSIM/LPIPS 不出现预定显著退化；逐 seed 展示；未见场景支持；不是少数图驱动 |
| 错误先验鲁棒性 | corruption excess loss 相对对应控制下降，且干净质量满足事先非劣界 | 全部预定扰动都报，至少一个未见 corruption family；主干旧先验通路与新增路由分开；不能只在训练扰动上证明泛化 |
| 效率 | 同权重或明确教师/学生协议下满足质量非劣界，并实测 wall-time 提升 | 包括先验与必要前处理；显存、NFE、硬件完整；成熟 DDIM 仅是基线，原创主张需额外方法 |

鲁棒性指标建议用损坏额外误差，或 PSNR 干净到损坏降幅的差：

\[
R_{s,g,k}=\big[m(C,\mathrm{clean})-m(C,\mathrm{corr}_k)\big]
-\big[m(M,\mathrm{clean})-m(M,\mathrm{corr}_k)\big].
\]

R>0 表示方法的降幅更小，但还要并列损坏状态绝对质量；一个很差的干净模型不能仅因几乎不再下降就被称为鲁棒。该式与干净非劣限制共同使用。

原协议的鲁棒门槛“下降减少 0.20 dB”是筛选选择，不是普遍标准；上一轮许多模型的某一损坏总降幅本身约 0.2 dB，机械复用可能近乎要求完全消除影响。可在不看新 holdout、只依据预先 pilot 的噪声尺度制定更合适的绝对/相对实际收益界，并保存理由；不能在结果出来后降低门槛直到通过。

**立即停止训练并保留记录的条件**：checkpoint身份不匹配、参考图/测试标签进入条件、场景重叠未解决且会影响主结论、NaN/Inf、无梯度/死分支、null不精确为零、预算预留不足以完成控制、resume状态不完整。此类失败先修复正确性，不以延长训练处理。

**科研停止条件**：完成预定最大步数和检查点后，候选对必要控制无可复核增量、跨 seed 方向显著不一致、鲁棒收益仅来自变差的 clean 输出、或新增成本超过冻结上限。输出 `not_supported_under_frozen_protocol`，不声称方向永久不可能，不自动改网络/新增数据/重开 400000 步。

**服务器交付最低验收**：

1. `PROTOCOL_V3_FROZEN.md/json`：主假设、范围、primary endpoint、comparison family、实际收益界、预算、seeds、checkpoint、数据和代码 hash。
2. `IMPLEMENTATION_CONTRACT_TESTS.md/json`：每条数学/形状/梯度/null/初始化/恢复契约的真实 PASS/FAIL 和运行命令。
3. `DATA_EXPOSURE_AND_SCENE_AUDIT.md/json`：旧测试暴露、候选近重复和已确认重叠分开。
4. `runs/.../`：完整 config、命令、日志、断点、训练/采样 seed、逐图指标、预算账本、失败状态。
5. `MATCHED_STEP_AND_SELECTED_CHECKPOINT_RESULTS.md`：固定步数主表、best-on-validation 副表、所有 seeds 和成本。
6. `MECHANISM_AND_FAILURES.md`：真实干预结果及不能支持的主张；门控热图不能替代机制证据。
7. `FINAL_EVIDENCE.md`：区分工程可用、探索信号、独立确认、未支持与资源阻塞。不以“已实现代码”等同“已形成创新”。
