The frozen UIEB train/val and test image bytes have no exact SHA-256 overlap. A 64-bit dHash screen flagged `61_img_` (val) versus `356_img_` (test), which visual inspection confirmed to be the same scene with different crop/size. `454_img_` versus `136_img_`, `726_img_` versus `136_img_`, and `454_img_` versus LSUI `291` were visually different scenes, hence perceptual-hash false positives. This screen is incomplete evidence for all possible near duplicates; it does not justify relabeling the frozen split as scene-disjoint. The final UIEB test should retain all 97 frozen images and also report an explicitly labeled 96-image sensitivity calculation excluding `356_img_`.

The RUOD release is retained as a candidate while permission and detector compatibility are checked. No detector AP or B depth accuracy has been measured. The 48-hour resource rule starts with this round's preparation; absence of a licensed dependency after that point will be recorded as `blocked_data` or `blocked_dependency`, without a fabricated substitute.

Atlantis provenance: the official Atlantis repository links the Kaggle dataset `zkawfanx/atlantis`; the Kaggle API identifies version 1, license `CC BY-NC-SA 4.0`, and describes the 400 depth images as **terrestrial** inputs for generation. The downloaded archive is `data/benchmarks/Atlantis/downloads/atlantis_v1.zip`, SHA-256 `6fc81e3c43a5333816e3b7d1fd7d8796d3a4db56cad6b3371664cfdd9bda08bf`. `unzip -tq` passed. Archive listing contains 400 `Atlantis/depth/NNNN.png` and 3200 `Atlantis/underwater/NNNN_XX.png` files, with no metadata or masks. A sampled pair is 672 x 512 pixels, despite the Kaggle description saying 512 x 512. This discrepancy must be resolved at decoding/registration audit before training. The shared base ID, not the generated variant, is the minimum grouping unit for train/val/test; a depth PNG reused by eight underwater variants cannot cross splits. An 8-bit generated depth target is a relative proxy, not a calibrated metric label. Source: https://www.kaggle.com/datasets/zkawfanx/atlantis and https://github.com/zkawfanx/Atlantis .

## 2026-10-03 follow-up provenance findings

The official Atlantis README at Git blob `9723770dc1ae98316b789dbe9d12503bae7e879f` says Depth2Underwater is trained using UIEB, and terrestrial conditioning depth is acquired with MiDaS. The MiDaS export source at its pinned submodule revision linearly min/max normalizes predictions to 8-bit grayscale without sign inversion. This supports inverse-depth export semantics in the documented pipeline, but is not a calibrated distance label or an independent provenance certificate for each released PNG.
